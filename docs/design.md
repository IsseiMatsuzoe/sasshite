# sasshite の設計

## 解決したい問題

調査や推論では、関連する仮説、対象外の範囲、未確認事項、代替案を広く扱う。そのすべてを返答へ並べると、受け手が「なぜ今これを読む必要があるのか」を解釈し直すことになる。sasshite は、調査結果から今回の会話に必要な発話を選ぶ判断を促す。

「推論用と応答用の自然言語が十分に分かれていない」という発想を、実装では**推論した内容と、今回伝える内容を区別する手順**として扱う。モデル内部の原因を断定するものではない。独立したモデル、追加の API 呼び出し、隠れた思考の記録は要求しない。

## 判断を共有し、表現はその場で決める

Skill の核は三つの判断である。

1. 現在の発話が、継続中の会話で何をしようとしているかを捉える。
2. 共有された前提と未解決事項を踏まえ、何を伝える意味があるかを選ぶ。
3. 受け手が理解・判断・利用できる順序で表現し、避けられる解釈や訂正の負担を残していないか見る。

これは内部の判断を整理したもので、回答の三段構成を指定していない。相談、対話、議論、経過報告、完成したレポートで、必要な内容と表現は変わる。ユーザーが指定した表・JSON・分量なども、そのまま守る。

長さ、段落数、結論の位置、見出し、語尾、必須の質問、必須の要約を最適化の代理指標にしない。説明を足すことで相手の推論負担が減る場合もある。十分な根拠を持つ反論や、頼まれた詳しい説明は残す。

## 省略の判断

| 内容 | 残す理由がある場合 | 省く理由がある場合 |
|---|---|---|
| 範囲や留保 | 結論の使い方・信頼・次の行動が変わる | 既に明らかな対象外を断るだけ |
| 共有前提の再説明 | 論理をつなぐ、誤解を直す、重要な合意を確かめる | 今回の論点を進めず、既知の説明を繰り返す |
| 確認質問 | 答えによって回答や行動が実質的に変わる | 文脈だけで十分に進められる |
| 共感や相づち | 受け止めること自体が会話の目的に寄与する | 中身と関係なく賞賛や感情の推測を加える |
| 次の提案 | 依頼の達成や明らかな実務上の必要を助ける | 返答の定番の締めとして付ける |
| 詳細な説明 | 理解や検証のために必要、または依頼されている | 分かったことをすべて列挙したいだけ |

削除の基準は新しい事実の有無だけではない。確認、納得、誤解の修復、気持ちを受け止めることにも役割がある。相手の属性だけから「知っているはず」「こう思っているはず」と決めない。

## tsuzuri からの変更

[tsuzuri](https://github.com/MaryCache/tsuzuri) の、書く前に意図を決める発想と、書き手の都合を読み手の利益から区別する考えを参考にした。原典のコミットと該当ファイルは [research.md](research.md) に記録した。

文書用の要件定義書・設計書・一文単位の記録や CLI 処理は移植していない。原典にある冒頭の形式指定も採用していない。対話では既に共有されている文脈を利用し、ユーザーの訂正を次の返答に反映する。見つかった欠落が内容に関わるなら、表現だけを整えず調査や推論へ戻る。

## GPT に向けた実装判断

OpenAI の [Skills の設計指針](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) と [reasoning model の指針](https://developers.openai.com/api/docs/guides/reasoning-best-practices) を踏まえ、ランタイムは一つの短い指示文にした。一般的な思考力の訓練、毎文の採点、長い内部独白、回答例の模倣は求めない。

研究メモや試験データは Skill の外に置き、通常の応答で読む必要をなくした。frontmatter は発火条件を記載し、OpenAI 用の UI メタデータだけを別ファイルにした。特定の API モデル ID、思考量、温度に依存しない。

Skills はホストが選択して読み込む指示であり、必ず毎ターン実行されるフックではない。今回の比較は明示的に適用した本文の効果を調べる。自動発火の精度は別の評価対象である。

## 評価で確かめること

同じ会話に、追加指示なし、簡潔さを求める短い指示、sasshite の三条件を適用する。評価では現在の問いへの適合、必要な情報の保持、根拠と不確実性の扱い、共有前提、不要な作業の押し戻しを確認する。

内容が欠けた短い回答を成功と扱わない。詳しいレポート、必要な確認質問、率直な反論、未検証事項の報告、指定された形式を守る例を含める。条件を隠した評価結果と生の回答を残し、改善が見られなかった例も公開する。人間の認知負荷そのものを測るには、別途、利用者の評価や実際の修正回数などが必要になる。
